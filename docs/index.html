Statistics whose last digit you can check.

cancho-stats is a command line for describing data and drawing inferences from it. Its sums are exact, its answers are the same bytes everywhere, and its error bounds were written before the code.

a real run, replayed 

  

  
Two real runs of stats describe on a Mac (Apple M4 Max): the file docs/example/readings.csv of this repository, and a file with a short record. The command prints one line of JSON, which the page wraps; nothing is elided or edited. It is a replay, not a live session. The numbers in it are the exact mean and variance of the doubles in the file, rounded once.






  
Trust the digits, not the library

  
A p-value is pasted into a report. Here its last digit has a stated error and a measurement behind it.

  

    
⚖
Exact where a sum decides
Sums, squares and products are accumulated exactly and rounded once, at the end. The order of the rows cannot change a bit.

    
📏
A bound written first
Every function has a relative error bound committed before its code, and a high-precision reference that tries to break it. When it broke, the bound was corrected in the open.

    
🔁
Same bytes everywhere
One committed fingerprint, equal on five machines and at 1 to 16 threads. No platform maths library is in any result.

    
🚫
Refusals are data
An input that cannot be answered gets a named rule, never a trap, a hang or a made-up number.

  






  
How it works

  
Exact accumulation, one rounding, then distribution functions checked against a reference that does not share their code.

  

  
  






  
How wide must an exact sum be?

  
S0 measured it against exact fractions, on 600 vectors in each of ten families.

  

    
🚫
Plain doubles
Inexact in 40 to 50% of vectors; up to 1.8e-13 off on cancellation.

    
⚠
Two-product into facc
Exact for exponent sums from -997 to 1003, and silently wrong outside. So a value outside 2^-485 ≤ |x| < 2^501 is refused.

    
✅
ml.fsq, 4196 bits
Exact for every finite double, for sums of squares. No range rule needed.

  

  
The rule that follows: squares through ml.fsq, products through the two-product with the refusal outside the range, one rounding at the end. Open: the exact numerator of variance and covariance needs a big-integer multiply that the compiler's library lacks; it is the first module of the next milestone.






  
The first command

  
stats describe FILE reads a CSV and describes each column. The mean and the variance come from sums that are exact and rounded once.

  

    
🧮
Exact, so it can be checked
The drift column of the example (readings near 1e8 that differ in the first decimal) has variance 0.022142858015639467, the exactly rounded value. The textbook one-pass formula in plain doubles gives -2.2857 on the same eight numbers (a negative variance; Python 3.14 on this Mac).

    
📄
Same bytes, any row order
Shuffling the rows of a file cannot change a byte of the answer, and the answer is the same on a Mac and on a Linux x86-64 machine. stats uses no threads, no clock and no network: the compiler proves it.

    
🚧
Refusals with a name
A short record is stats.csv-ragged, exit 8, with the line number. 25 refusal cases and 5,000 hostile files are in the gates: no trap, no hang, one line of JSON.

  

  
Measured: 1,000 generated files, 40,078 values, every one bit for bit equal to exact fractions rounded once, and 26 of 26 mutants of the program killed. Not built yet: skewness, kurtosis, quantiles, histogram, distinct counts, --by.






  
Measured, not promised

  
Normal, Student t, chi-square, F and binomial, with survival functions that never lose a tail, and the normal quantile.

  

    
0 / 432,000cases outside the bound, 27 ranges at full size, after one correction

    
1.6×the worst miss the full-size run found before the correction (a bound was 4e-16, it needed 1e-15)

    
5machines with a byte-identical fingerprint, at 1 to 16 threads

    
73 + 12mutants killed, and survivors each explained, of 85

  

  
Measured on seeded samples at the exact input doubles, against mpmath at 60 digits and more; scipy.special is a second reference and is the outlier on the binomial by up to 3.4e-9. The closest ratio to a bound is 0.97, so that bound is tight, not comfortable. The error is bounded only in the ranges stated in docs/numerics.md.






  
Try it

  
You need the cancho compiler at the revision in cancho.toml and Python 3.


git clone https://github.com/alpibrusl/cancho-stats.git
cd cancho-stats
export CANCHO=<path-to-the-cancho-binary>
"$CANCHO" install
"$CANCHO" build --bin stats
build/stats describe docs/example/readings.csv
"$CANCHO" build --bin special-check
python3 -m venv .venv && .venv/bin/pip install -r ci/requirements.txt
sh scripts/check.sh            # every gate, minutes
echo "1 4000000000000000 4024000000000000" | build/special-check t_sf
1 3fa2c98ee9420ee7 0           # t_sf(2, df 10): the bits of the answer
