# `stats test`: design (milestones S3 and, for the rank and exact tests, S4)

**Status: design only, written 2026-10-23 before any code of S3. Nothing here has been measured for `test`; what it reads from the code of S0 to S2 is marked [read], every bound is a [choice] fixed before the first run and corrected in place, in this document, if a run shows it false.** Tags: **[read]** read from a document or source, **[measured]** printed by a script (none yet), **[choice]** a decision the maintainer can overturn, **[open]** not decided. Issue #4. S3 is the t family, the chi-square test, the test of proportions and the correction for several tests; the rank tests, ANOVA, Kruskal-Wallis, Kolmogorov-Smirnov and Fisher are S4 (issue #5) and are not designed here.

## 1. What it does

`stats test KIND FILE [flags]` reads a CSV with the reader of `describe` and `corr` and prints one JSON document (`stats.v1`) with one entry per test. Every test answers the same fields (`docs/design.md` section 6):

```
{"test":"t2","column":"temp","statistic":..,"df":..,"p_value":..,"p_method":..,
 "effect_size":{"name":"cohen_d","value":..},"interval":{"level":0.95,"low":..,"high":..,"of":"difference of means"},
 "n":{"a":..,"b":..},"method":"welch","assumptions":{..facts..},"reason":..}
```

`assumptions` holds **facts** (sizes, the ratio of variances, expected counts below 5), never a verdict. `reason` is present when something is `null` (as in `corr`). Numbers are the decimal text of correctly rounded doubles, except where this document says a number is computed in floating point from exact pieces (the interval endpoints, section 3).

## 2. The kinds and what they compute **[choice]**

With `n`, `Sx = sum x`, `Sxx = sum x^2` exact (the accumulators of `describe`, **[read]** `lib/acc/psum.cho`), the mean is `m = Sx / n` and the sum of squares about the mean is `L = n Sxx - Sx^2` (an exact integer, the `L2` of `describe`, **[read]** `lib/acc/central.cho`), so the sample variance is `v = L / (n (n - 1))`.

| kind | question | inputs | statistic | df |
|---|---|---|---|---|
| `t1` | is the mean of a column `mu0`? | `--cols A,B,..` `--mu0 0` | `t = (m - mu0) / sqrt(v / n)` | `n - 1` |
| `t2` | do two groups have the same mean? | `--cols A,B,..` `--group G` (a column with exactly two levels), `--variance pooled` for the pooled test | Welch: `t = (m1 - m2) / sqrt(v1/n1 + v2/n2)` | Welch-Satterthwaite `(a + b)^2 / (a^2/(n1 - 1) + b^2/(n2 - 1))`, `a = v1/n1`, `b = v2/n2`; pooled: `n1 + n2 - 2` |
| `paired` | is the mean of the differences zero? | `--pairs A:B,C:D` | `t1` of `a - b` over the rows where both are present | `n - 1` |
| `chisq` | are two categorical columns independent? (or does one match given proportions?) | `--cols A --vs G`, or `--cols A --expected p1,p2,..` | `X2 = sum (O - E)^2 / E` | `(r - 1)(c - 1)`, or `k - 1` |
| `prop` | is a proportion `p0`? do two groups have the same one? | `--cols A --success LEVEL` `--p0 0.5`, with `--group G` for two groups | `z = (x - n p0) / sqrt(n p0 (1 - p0))`, or the pooled two-sample `z` | none (normal) |

* **Welch is the default for `t2`** (the design of `docs/design.md` section 4); `--variance pooled` is the explicit pooled test (**corrected 2026-10-24, in S3.2:** the design said `--equal-var`; the flag is `--variance welch|pooled` because the tool's flags are values, never switches, and a name that says what is chosen reads better than one that says what is assumed). The answer says which in `method` (`welch` or `pooled`), and `assumptions` carries `variance_ratio = v1 / v2` (null when `v2` is 0).
* **Groups and pairs (S3.2).** The group column's cells name the groups; a row whose cell is empty has no group and is dropped; with other than two levels the call is refused (`stats.group-levels`). The group `a` is the level that is first **by its bytes** (`10` before `9`), `b` the other; the difference is `a - b`, and the answer names both levels (`levels: {a, b}`). A `paired` entry is named by `pair: [A, B]`, not by `column`, and the difference is `A - B`; a name that has a colon in it cannot be given to `--pairs`.
* **The statistic is an exact rational, rounded once.** `t^2` is a ratio of exact integers built from the two groups' `n`, `Sx` and `L` (the algebra is written twice, in `lib/test/` and, independently, in the oracle of section 5), `t` is `sign * sqrt(t^2)` through `central.sqrt_ratio_bits`, as the correlation coefficient is. `df` of Welch is an exact rational rounded once to a double (it is a real number; `t_sf` takes a real `nu`). `t^2` and `df` are never formed from rounded means or variances.
* **Effect size, one per kind, named in the answer:** `t1` and `paired` `cohen_d = (m - mu0) / sd` (`d_z` for `paired`); `t2` `cohen_d = (m1 - m2) / sd_pooled` (pooled with `n1 + n2 - 2`, also under Welch: the effect size is the standardised difference, whichever test); `chisq` Cramer's `V = sqrt(X2 / (N (min(r, c) - 1)))`; `prop` Cohen's `h = 2 asin(sqrt(p1)) - 2 asin(sqrt(p2))` for two groups and the difference `p - p0` for one. The ones that are a square root of an exact rational are rounded once; `h` is computed in doubles from the two exact proportions and is said to be (`rounding` in the answer).
* **The interval** is the confidence interval for the quantity the test is about: the mean (`t1`), the difference of means (`t2`, `paired`), the proportion or the difference of proportions (Wilson for one group, Newcombe's hybrid-score for two **[open]**), none for `chisq` (its effect size has none in v1). Its endpoints are `estimate -+ q * se` with `se` exact-then-rounded once and `q` the Student `t` quantile (`special.quantile.t_quantile`, **[read]**, S0b) or the normal one: **the endpoints are floating-point arithmetic on two correctly rounded numbers and a quantile that is accurate to about 1e-12, not correctly rounded**, and the answer says so (`rounding: "double"`). The level is `--level 0.95`, strictly between 0 and 1.
* **p-values.** `t`: two-sided `2 t_sf(|t|, df)`; `chisq`: `chi2_sf(X2, df)`; `prop`: `2 norm_sf(|z|)` (**[read]** `special.dist`). Their accuracy is the distribution function's (relative 1e-12 for Student `t`, 2e-13 for the normal and for chi-square up to 10,000 degrees of freedom, **[read]** `docs/numerics.md` section 3.2) plus the amplification of the rounding of the statistic: the bound of the gates, with a margin over those, is in section 5. **[open]** one-sided tests (`--alternative less|greater`): proposed for after v1, with the same exact statistic and the open-ended interval.
* **Missing cells** are dropped per column (`t1`, `t2`) and per pair (`paired`); the sizes used are in `n`. A group column cell that is missing drops the row.

## 3. Exactness plan

* `t1`, `t2`, `paired`: per column (and per group), the accumulators `psum` k = 1, 2 over the rows used; `L`, `m` and the cross terms in `acc.bigint` as in `describe` and `corr` (built with the `pub` helpers of `central.cho` that `corr` already uses). The one new piece is `central.sqrt_ratio_bits_exp`, the exact square root of a ratio times a power of two: the standard error `sqrt(L / (n^2 (n - 1)))` is in units of 2^-1074 and must be rounded once in those units.
* **The null mean `mu0` is a double** (parsed by `flt.parse_float`) taken as exactly the number it is, in the unit 2^-1074 of `Sx`: `D = Sx - n mu0` is then an exact integer and `t^2 = (n - 1) D^2 / L`. The level is a decimal with at most 9 decimals, so `(1 - level) / 2` is the quotient of two integers below 2^53, correctly rounded by one division.
* `chisq`: the cells are counts (integers). `X2 = N (sum n_ij^2 / (r_i c_j) - 1)` is a sum of rationals with different denominators; an exact sum would need the common denominator of up to `r c` products of row and column totals, which is out of reach for large tables. **[choice]** each term `(N n_ij - r_i c_j)^2 / (N r_i c_j)` is formed as an exact rational and rounded to 106 bits (double-double, `special.dd`, **[read]**) and the terms are summed in double-double, the sum rounded to a double: the result is the correctly rounded value unless the exact `X2` is within about 2^-100 (relative) of a tie between two doubles, which the oracle checks bit for bit on generated tables and reports. This is the one place in S3 where "exact, rounded once" is "exact except within 2^-100 of a tie", and the answer says so (`rounding: "double-double"`).
* A categorical column needs, per row, the index of its level. `describe` counts levels in a second pass over the file (**[read]** `level_pass`), keeping only counts; `chisq` and `prop` need the level of every row, so S3 adds a pass that records, per chosen column, a level index per row (bounded by `--max-levels` and `--max-cells`, refused with the limit tags that exist) and the table of levels in order of first appearance.
* Determinism: no `conc`, the same bytes at any thread count and row order (the sums are order-free; the levels are numbered by their bytes, not by first appearance, so a shuffle of the rows cannot change the order of the table).

## 4. Several tests: `--correct` **[choice]**

A call that names several columns (`--cols A,B,C`, or `--pairs`) is a **family**: one test per column, all the same kind. `--correct bonferroni|holm|bh` adds `p_adjusted` to each entry and `family: {"size":m,"correction":..}` at the top; without `--correct` the answer has `adjustment: "none"` and the p-values stand alone, as `corr` does. The adjustments are exact rational arithmetic on the unrounded p-values' doubles: Bonferroni `min(1, m p)`, Holm the step-down maxima, Benjamini-Hochberg the step-up minima, each monotone and capped at 1; ties in the p-values are ordered by column order so the answer is deterministic. The correction does not change `p_value`.

## 5. Gates (written before the code, each able to fail)

| id | gate | fails when |
|---|---|---|
| T-A | **Exact statistics**: `t`, `df`, the effect size and `n` of `t1`, `t2` (Welch and pooled), `paired`, `chisq` (independence and goodness of fit) and `prop` (one and two groups) against `Fraction` formulas written independently of the program (the oracle works from the data, never from the program's intermediate sums), bytes compared; families of files with offsets, wide exponents, missing cells, constant groups, groups of size 1 and 2, tables with empty cells | one byte differs |
| T-B | **p-values against `mpmath`** at 60 digits from the exact rational statistic: relative `1e-11 + (df + 1) 2^-53` for `t` (the rounding of `t` amplified by at most `df + 1`), `1e-11 + (X2 + 1) 2^-53` for `chisq` (amplified by the exponent of the tail), `1e-11 + (z^2 + 1) 2^-53` for `prop`, for p-values down to `1e-300` (below that the answer must be under `1e-290`). **Controls** (must fall outside): the pooled test where Welch is meant, `n` for `n - 1` degrees of freedom, one-sided for two-sided, the normal for Student's `t`, Yates's correction where none is meant | outside the bound; a control inside it |
| T-C | **Intervals**: endpoints against `mpmath` with the bound `1e-12 * max(|estimate|, half-width)` absolute, and never below two units of 2^-1074 (the endpoints are floating-point arithmetic on exact pieces, section 2; the floor is for endpoints in the subnormal range, where no double is closer to the exact value than its spacing: added after the first run, which had 8 such cases). **Corrected in S3.2:** for `t2` and `paired` the floor is `2 + q` units, `q` the quantile of the answer: the standard error is a double, half a unit off in that range, and `q` multiplies it (the first run of `paired` had an endpoint 2.4 units off with `q` = 5.8; `t1` keeps its two units) | outside the bound; the controls (the normal quantile for the `t`, `n` for `n - 1`) must fall outside |
| T-D | **scipy**, reported with the bounds fixed here: `ttest_1samp`, `ttest_ind(equal_var=False)` and `True`, `ttest_rel`, `chi2_contingency(correction=False)` and `chisquare`; the z test of proportions is compared with the formula of the oracle only (statsmodels is not a dependency and scipy has no such function); statistic to `1e-12` (relative above |t| = 1, absolute below: near t = 0 scipy's float cancellation decides its own answer, as the first run showed) and p-value to `1e-9` relative on well-conditioned data (not the offset-`1e8` family, where scipy's own float sums lose digits: printed, not gated) | outside the bound on a well-conditioned family |
| T-E | **Calibration** under a true null, seeded, 4,000 replicates at sizes 5, 10, 30, 100, 1,000: the rate at which `p < 0.05` inside the two-sided 99.9% binomial interval and the p-values uniform (KS, p > 0.001) for `t1`, `paired`, Welch `t2` **with unequal variances and unequal sizes** (Welch must hold where the pooled control must not), and the pooled `t2` under equal variances; `chisq` with all expected counts at least 5 (smaller tables are printed, not gated: the chi-square approximation is the thing known to fail there, and `assumptions` reports the count); `prop` for `n p0` and `n (1 - p0)` both at least 10 (printed otherwise). (For Welch's test a group of 3 is the exception, **corrected after the first run of S3.2**: its approximation is conservative there, 129 rejections of 4,000 at the nominal 5% with equal variances (a KS p-value of 0.000), while the pooled test on the same data is exact; the p-value is the exact Welch formula (T-A), so this is the test and not the program, and Welch is gated from 5 per group on, printed below.) The sizes include n = 3: with the control of `n` for `n - 1` degrees of freedom the smallest size that the replicates can tell apart is 3 (at n = 5 the rejection rate of the control, 6.2%, is inside the interval). Whatever size the corr gates found to be a lattice problem is gated by the rate only, as in `docs/corr.md` section 8 | a wrong tail, degrees of freedom or variance: each control must be refused at some size |
| T-F | **Power and coverage**: a planted difference of known size is rejected at the rate the noncentral `t` gives (`mpmath`, bound by the binomial interval); a 95% interval covers the true mean/difference at 95% (binomial interval), for `t1` and Welch `t2` | outside the interval |
| T-G | **Correction**: `holm`, `bh`, `bonferroni` against `Fraction` implementations, the monotonicity and the caps (a property test over random p-vectors), and the family-wise error rate of `holm` and the false-discovery rate of `bh` under a seeded null of 20 columns at the nominal level | a violated property; a rate outside its bound |
| T-H | **Invariance**: 50 row permutations give the same bytes; swapping the order of the two groups negates the statistic and the difference and leaves `p`, `df`, `|d|` and the interval's width; the columns of a family given in another order give the same entries in the order of the file | one byte differs |
| T-I | **Fuzz**: groups of size 0, 1, 2, constant groups, a group column with 1, 2, 3 levels and a missing level, huge and subnormal values, a table of one cell, an expected count of 0, `--level` at its edges, hostile files and arguments: no trap, no hang, every refusal tagged | a trap or an untagged refusal |
| T-J | **Mutants** for every kind (killed, or each survivor explained), and **the fingerprint** lines `test-*` in `docs/xplat_fp.txt` equal on the runners of the workflow | an unexplained survivor; a differing line |

## 6. Output, refusals

* Rule tags **[choice]**: a kind that does not exist is `args.bad-value` on the second operand (no new tag); `stats.group-levels` (the `--group` column has other than two levels; the detail says how many and the repair names `--cols` and a filter), `stats.non-numeric` (shared with `corr`), `stats.no-such-column`, `stats.ambiguous-column`, `stats.test-columns` (no column named for the kind, or `paired` without pairs), `limit.too-many-tests` (the family is larger than `--max-tests`, default 1,000), `limit.table-too-large` (`chisq` with more than `--max-cells` cells in its table), `args.bad-value` for `--level`, `--mu0`, `--p0` outside their ranges. A statistic that is undefined is `null` with a `reason` (`too-few-rows`: a group below 2 rows; `variance-zero`: both groups constant, or `t1` on a constant column; `empty-expected`: an expected count of 0), never a refusal.
* The authority of `stats` does not change (no `conc`, no clock, no network).

## 8. Decisions of 2026-10-23 and what is still open

The maintainer merged this design and said to continue without changing the proposals: they stand as written in sections 2 to 7 (the input form of point 1, no one-sided tests in v1, Newcombe's hybrid score for the two-sample proportion interval, `chisq` in double-double, Cohen's `d`, no `--by` family). Each can still be overturned. The points as they were put:

1. The input form: columns named by `--cols`, a two-level `--group` for `t2` and `prop`, `--pairs A:B` for `paired`, `--vs` for `chisq`. The alternative is a long format (a value column and a group column) for every kind.
2. `--alternative less|greater`: proposed after v1.
3. The two-sample interval for proportions: Newcombe's hybrid score (proposed) or the Wald interval, which is simpler and worse.
4. `chisq` in double-double (section 3) against refusing tables whose exact sum needs a bigger denominator than a stated size (exact, but only small tables): proposed double-double, said in the answer.
5. Cohen's `d` or Hedges' `g` as the `t` effect size (proposed: `d`, with the factor of `g` as a separate field later).
6. Whether `stats test` also runs one test per level of a `--by` column (a family made by grouping), which would make `--correct` useful on one column.

## 10. S3.3 `chisq`: decisions before the code (2026-10-24)

All **[choice]**; each can be overturned. Nothing here is measured yet.

* **Input.** `stats test chisq --cols A[,B,..] --vs G FILE`: the independence of each named column and `G` (one entry per column, `G` the same for all), or `stats test chisq --cols A[,B,..] --expected p1,p2,..,pk FILE`: the goodness of fit of each column to the proportions. Exactly one of `--vs` and `--expected` is required (`stats.test-columns` otherwise). A column here is **categorical**: its levels are the distinct non-empty cells, compared by their bytes (a numeric column is allowed, `1` and `1.0` are two levels), ordered by bytes; a row with an empty cell in either column of a pair is dropped for that pair, and the answer says how many (`n.missing`). `--expected` takes `k` decimals with at most 9 decimals each, all above 0, that add up to exactly 1 (decimal arithmetic, not doubles), in the order of the levels by bytes; `k` must be the number of levels of the column (else `stats.expected-proportions`, with both numbers). The levels are numbered by their bytes and the table is counted with them, so no order of the rows can change a bit.
* **Levels and cells.** The most levels of a column are `--max-groups` (default 50, ceiling 1,000; the tag `limit.too-many-groups` that `--by` has), so a table has at most 1,000,000 cells and `limit.table-too-large` of the design is not needed. A level that has no complete row (its rows all have the other cell empty) is not a level of that pair.
* **Statistic and rounding.** `X2 = sum (N n_ij - r_i c_j)^2 / (N r_i c_j)` (independence) or `sum (O_i D - N P_i)^2 / (N P_i D)` with `p_i = P_i / D`, `D = 10^9` (fit): each term is a quotient of two exact integers (numerator below 2^106 as a product of two 47-bit integers, denominator below 2^80 as a product of up to three), formed in double-double (`special.dd`), summed in double-double, rounded to a double: **correctly rounded except when the exact sum is within about 2^-100 (relative) of a tie between two doubles**, and the answer says so (`rounding: "double-double"`). `df = (r - 1)(c - 1)` or `k - 1`. The p-value is `chi2_sf(X2, df)`.
* **Effect size.** Cramer's `V = sqrt(X2 / (N (min(r, c) - 1)))` for independence, Cohen's `w = sqrt(X2 / N)` for fit, computed in doubles from the rounded `X2` (`rounding: "double"`: three roundings, gated to 4 ulp), not one.
* **Assumptions are facts:** `table` `{rows, cols}` (or `levels`), `min_expected` (the smallest expected count, a double), `expected_below_5` (how many cells have an expected count under 5; counted exactly, `r_i c_j < 5 N`). No verdict.
* **Refusals and nulls.** A table with one level in a column has `df` = 0: the statistic, p-value and effect size are null with `reason: "too-few-levels"`. Otherwise no statistic is null. `--expected` with a proportion that is 0, malformed, a count different from the levels, or a sum other than 1 is `stats.expected-proportions`.
* **Gates (T-A to T-E, T-I for `chisq`).** The oracle is `Fraction` for the exact `X2` (both forms), `mpmath` for the p-value at the exact rational and the degrees of freedom: `X2` bit for bit with the correctly rounded exact value (a mismatch is **counted and reported**, expected 0 in thousands of tables), `df`, `V` and `w` within 4 ulp, `min_expected` within 2 ulp, `expected_below_5` and `n` exactly, the p-value within `1e-11 + (X2 + 1) 2^-53` relative. Controls (each must leave the bound on a tenth of the tables): `X2` with Yates's correction, the degrees of freedom `r c - 1`, the G statistic in place of Pearson's, expected counts from the wrong margin. scipy (`chi2_contingency(correction=False)`, `chisquare`) on well-conditioned tables, reported with the bounds of T-D. Calibration under independence (a table from the product of margins) and under a true fit, with all expected counts at least 5, and the p-values uniform (KS, from the sizes where the lattice does not matter); tables with expected counts under 5 are printed, not gated. Refusals and fuzz for the new tags; mutants; fingerprint lines `test-chisq`.

## 11. S3.4 `prop`: decisions before the code (2026-10-24)

All **[choice]**; each can be overturned. Nothing here is measured yet.

* **Input.** `stats test prop --cols A[,B,..] --success LEVEL [--p0 0.5] FILE` is the one-sample test of the proportion of rows whose cell in each column is `LEVEL`; adding `--group G` (a column with exactly two levels, as for `t2`) tests that the two groups have the same proportion. `--success` is required (`stats.test-columns`); a cell is a success when its bytes (between the quotes, as for `chisq`) equal `LEVEL`. The trials of a column are the rows whose cell is not empty (and, with `--group`, whose group cell is not empty); the answer says how many rows were left out. A column with no success (or all successes) is a proportion of 0 (or 1), not a refusal. `--p0` is a decimal with at most 9 decimals strictly between 0 and 1 (default 0.5); with `--group` it is refused (`args.bad-value`: the two-sample test has no null value).
* **Counting.** The same pass as `chisq` (`lib/csvx/cross.cho`): the levels of a column are counted with `--max-groups` as their bound, the count of `LEVEL` is read from the table. The group `a` is the level first by bytes, the difference is `a - b`.
* **Statistic, one sample.** With `x` successes of `n`, `p0 = P / D` (`D = 10^9`): `z^2 = (x D - n P)^2 / (n P (D - P))`, `z = sign * sqrt(z^2)`, **one rounding of an exact rational** (`central.sqrt_ratio_bits`, as `t`). The difference `p - p0 = (x D - n P) / (n D)` and the proportion `x / n` are also one rounding each. **Two samples (pooled):** `z^2 = (x1 n2 - x2 n1)^2 N / (n1 n2 X (N - X))` with `X = x1 + x2`, `N = n1 + n2`; `p1 - p2 = (x1 n2 - x2 n1) / (n1 n2)`. The statistic is `null` with `reason: variance-zero` when `X` is 0 or `N` (the pooled variance is 0), `too-few-rows` when a group has no trial.
* **p-value.** `2 norm_sf(|z|)` (`special.dist`, 2e-13 relative), `p_method: "normal"`, `df` null. **No continuity correction** (the design of section 2 names none; `chisq` has none either); the gate carries Yates's correction as a control.
* **Intervals** (`rounding: "double"`, endpoints in doubles from the exact proportions and the normal quantile `q = qnorm((1 + level) / 2)`): **Wilson's score interval** for one sample, centre `(x + q^2/2) / (n + q^2)`, half-width `q sqrt(x (n - x) / n + q^2/4) / (n + q^2)`, clamped to [0, 1]; **Newcombe's hybrid score interval** (method 10) for two samples: `d - sqrt((p1 - l1)^2 + (u2 - p2)^2)` to `d + sqrt((u1 - p1)^2 + (p2 - l2)^2)` with `(l_i, u_i)` the Wilson interval of group `i`. The bound of the gate is absolute 1e-11 (the quantile is accurate to about 1e-12).
* **Effect size.** One sample: the difference `p - p0` (`effect_size.name: "difference"`, one rounding). Two samples: Cohen's `h = 2 asin(sqrt(p1)) - 2 asin(sqrt(p2))` (`"cohen_h"`, `rounding: "double"`, computed from the proportions as doubles with `atan2`; the gate bound is absolute 1e-12).
* **Assumptions are facts:** one sample `n_p0` and `n_1_minus_p0` (the expected counts of the normal approximation, exact then rounded once), two samples `pooled` (the pooled proportion) and the two expected-count minima. No verdict.
* **Gates.** The oracle is `Fraction` for the exact `z^2`, differences and proportions, `mpmath` for the p-value at the exact `z` and for the Wilson and Newcombe endpoints at 60 digits. Statistic and difference **bit for bit**; p-value within `1e-11 + (z^2 + 1) 2^-53` relative; intervals within 1e-11 absolute; `h` within 1e-12 absolute. Controls (each must leave the bound on a tenth of the cases): the Wald interval, Yates's continuity correction, the unpooled two-sample `z`, `2 t_sf` in place of the normal, the one-sided p-value. scipy has no such test; the one-sample `z` is compared with `scipy.stats.binomtest` only as a reported figure (its exact test is a different test). Calibration under a true null (`n p0` and `n (1 - p0)` at least 10, 4,000 replicates, rate and KS from the sizes where the lattice does not matter; the two-sample under equal proportions) and the **coverage of the Wilson and the Newcombe intervals** (nominal rate within the binomial interval at the sizes where the approximation is known to hold; the Wald control must be refused at small `n`). Refusals and fuzz for the new inputs, mutants, fingerprint lines `test-prop`.

## 12. S3.5 `--correct`: decisions before the code (2026-10-24)

All **[choice]**; each can be overturned. Nothing here is measured yet. Section 4 stands, with the changes below, which correct it in place.

* **Flags.** `stats test KIND .. --correct none|bonferroni|holm|bh` (default `none`) and `--max-tests N` (default 1,000, ceiling 32,640): a call that names more columns, pairs or items than `--max-tests` with a correction other than `none` is `limit.too-many-tests` (the tag of section 6). `--correct` with `describe` or `corr` is `args.bad-value` (their p-values are not a family of tests of one question; `corr` keeps `adjustment: none`).
* **The family** is the entries of the answer that have a p-value; an entry whose p-value is `null` (a constant column, a group with no trial) is not counted in `m` and has `null` for its adjusted value. Entries of one call are one family, whatever the kind.
* **Where the result goes (correction of section 4).** Section 4 said each entry gets `p_adjusted`. The entry writers do not see each other, so the adjusted values are one array **after the tests**, aligned with `tests` and the same length: `"family": {"size": m, "correction": "holm", "p_adjusted": [..]}`, and the header says `"adjustment": "holm"` in place of `"none"`. `p_value` of an entry is never changed.
* **The arithmetic is exact.** The p-values are the doubles that were printed. With `m` entries sorted by p-value (ties by the order of the entries; **the order of equal p-values cannot change an adjusted value**, the running maximum or minimum makes tied entries equal: the sort is stable for determinism of the code and the gate has no control for it), `p(1) <= .. <= p(m)`: Bonferroni `min(1, m p)`; Holm `p~(r) = max over j <= r of min(1, (m - j + 1) p(j))`; Benjamini-Hochberg `p~(r) = min over j >= r of min(1, m p(j) / j)`. Each product or quotient of a double and small integers is an exact rational (`central.ratio_bits`) **rounded once**; the maxima and minima of correctly rounded values are the roundings of the maxima and minima, so the result is the correctly rounded exact adjusted p-value.
* **Gates (T-G).** `Fraction` implementations in the oracle (written from the definitions, with a different sort) against the program's `p_adjusted` bit for bit on families of 1 to 60 entries made of every kind of test (ties, p-values of 1, p-values near 0, null p-values), and the properties on random p-vectors: `p <= p~ <= 1`, the order of the p-values kept, Bonferroni >= Holm >= BH ... where the definitions say so (Holm <= Bonferroni, BH <= Holm), `m = 1` changes nothing. The family-wise error of Holm and the false-discovery rate of BH are measured under a seeded null of 20 columns at the nominal level (the rate of at least one false rejection of Holm inside the binomial interval below 5%; the mean false-discovery proportion of BH with half of the nulls true below 2.5% plus a margin fixed here: three standard errors); the control without correction must be refused (its family-wise rate is 64%).
